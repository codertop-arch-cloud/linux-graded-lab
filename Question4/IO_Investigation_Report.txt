2. FILE DESCRIPTOR OBSERVATIONS
----------------------------------------------------------------------
Technical Details:
In the output above, look closely at the 'FD' (File Descriptor) column:
- 'cwd': Represents the Current Working Directory of the process.
- 'txt': Represents the program text (e.g., the '/bin/zsh' binary code and its libraries).
- '0': Represents File Descriptor 0 (Standard Input / stdin), which is linked to a system pipe.
- '1': Represents File Descriptor 1 (Standard Output / stdout), which is also mapped to a pipe.
- '2': Represents File Descriptor 2 (Standard Error / stderr), mapped to the same output pipe.
- '10r': Represents File Descriptor 10, open for reading from '/dev/null'.

*Linux-specific note*: In a native Linux environment, these active descriptors can be investigated dynamically by listing the directory `/proc/<PID>/fd/` (e.g., `ls -l /proc/self/fd/`), where each descriptor is represented as a symbolic link pointing to the opened file or resource.

5. HOW LINUX MANAGES FILE I/O
----------------------------------------------------------------------
In Linux, I/O operations are governed by three primary kernel-level tables:

1. Process-Specific File Descriptor Table:
   Each running process maintains its own array of file descriptors (0, 1, 2, 3...). Each integer index contains a pointer that references an entry in the system-wide Open File Table.

2. System-Wide Open File Table:
   This kernel table tracks all open files system-wide. Each entry contains vital details about the open instance, including the file status flags (read, write, append, non-blocking), the current file offset (where the next read/write will occur), and a pointer to the Virtual File System (VFS) inode table entry.

3. Inode Table (VFS Inode):
   The Virtual File System (VFS) inode table references the physical file information on disk. It contains basic metadata (permissions, file size, owner) and pointers to the physical blocks containing the file contents on the disk media.

Redirection Mechanics:
- When standard output redirection (`>`) occurs, the kernel updates the process's file descriptor table entry for FD 1 (stdout) to point to the open file entry of `output.log` in the system-wide table.
- When error redirection (`2>`) occurs, the table entry for FD 2 (stderr) is updated to point to `error.log`.
- Through this mechanism, programs can write to stdout/stderr using standard write calls, while the operating system seamlessly route the bytes to different files, pipes, or screens without program modifications.
