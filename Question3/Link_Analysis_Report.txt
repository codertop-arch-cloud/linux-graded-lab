Expected Output:

Explanation of Commands:
The 'rm' command deletes the 'original.txt' directory entry, reducing the link count of inode '67125766' from 2 to 1. Reading 'hardlink.txt' succeeds because the underlying data block and its inode remain intact, whereas reading 'symlink.txt' fails because its target file path no longer exists, resulting in a dangling link.

6. TECHNICAL COMPARISON: HARD LINK VS. SYMBOLIC LINK
----------------------------------------------------------------------
Below is a comparison summarizing findings from this experiment:

| Feature                   | Hard Link                                | Symbolic (Soft) Link                    |
|---------------------------|------------------------------------------|------------------------------------------|
| Inode Association         | Shares the exact inode of the target file | Has its own unique, independent inode    |
| Link Count Behavior       | Increases link count of target inode     | Does not affect target inode link count  |
| File Size                 | Same size as target file                 | Very small (stores length of path name)  |
| Directory Traversal       | Cannot link directories (on most OS)     | Can link files and directories           |
| Cross File-System         | Restricted to the same file system       | Can span across different file systems   |
| Behavior on Source Delete | Data remains accessible via hard link    | Becomes broken / dangling symlink       |

----------------------------------------------------------------------
7. CONCLUSIONS
----------------------------------------------------------------------
- Hard links are directory pointers directly referencing a file's raw inode data. As long as at least one hard link exists (link count > 0), the file data remains fully intact on disk.
- Symbolic links are shortcut files containing the pathname of the target. If the target file is renamed or deleted, the symlink breaks because its text reference points to a non-existent path.
- The experiment clearly demonstrates how accidental file deletion can be mitigated by hard links, and why soft links are highly dependent on the absolute/relative path of the target file.
