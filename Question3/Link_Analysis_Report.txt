10. TECHNICAL COMPARISON: HARD LINK VS. SYMBOLIC LINK
----------------------------------------------------------------------
Below is a comparison summarizing findings from this experiment:

| Feature                   | Hard Link                                | Symbolic (Soft) Link                    |
|---------------------------|------------------------------------------|------------------------------------------|
| Inode Association         | Shares the exact inode of the target file | Has its own unique, independent inode    |
| Link Count Behavior       | Increases link count of target inode     | Does not affect target inode link count  |
| File Size                 | Same size as target file                 | Very small (stores length of path name)  |
| Directory Traversal       | Cannot link directories (on most OS)     | Can link files and directories           |
| Cross File-System         | Restricted to the same file system       | Can span across different file systems   |
| Behavior on Source Delete | Data remains accessible via hard link    | Becomes broken / dangling symlink       |

----------------------------------------------------------------------
11. CONCLUSIONS
----------------------------------------------------------------------
- Hard links are directory entries directly pointing to a file's raw inode. The underlying file data remains accessible on disk as long as at least one hard link exists (link count > 0).
- Symbolic links are distinct shortcut files containing the pathname of the target. If the target file is deleted, the symlink breaks because its text reference points to a non-existent path.
- This experiment demonstrates how hard links can protect against accidental deletion of specific directory entry links, whereas symbolic links are flexible (can span across partitions/devices) but completely dependent on the persistence of their target paths.
